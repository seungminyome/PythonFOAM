PythonFOAM: a vision-language observer for OpenFOAM runs

An optional observer for the PODFoam example of PythonFOAM. While OpenFOAM runs, Python draws |U| and p and asks a picture-reading model on the same node what it sees. The answers are recorded, and nothing goes back into the solver. The README says how to run it.

What the model sees: |U| and p at step 250 of a developed backward-facing-step flow, drawn by the running solver and sent to Google's Gemma 4 12B.

What we found

The model was Gemma 4 12B unless a row says otherwise. It got a question together with the two pictures above, or with a short sequence of them.

The branches pr/podfoam-fix and pr/podfoam-observer build and pass the bridge validation on OpenFOAM v2012, v2106, v2212 and 8. They are prepared for pull requests to PythonFOAM. The bridge validation runs ten time steps of PODFoam and checks the round trip of snapshots and POD modes between C++ and Python. Both branches also fix a bug in the original PODFoam, where the next snapshot overwrote the first snapshot of each SVD window.

Key numbers

A position counts as right when it lies within 10 % of the plotted range of the true position. The fixed guess is the best single answer given to every picture. The table also gives a simple rule on the field values or a regression for each test where it did better than a model. The four models are Gemma 4 12B, 26B-A4B and 31B, and Qwen3.5-35B-A3B. Limitations

  • The tests used 2D laminar flows and one extruded 3D case.
  • Only positions and words from a fixed list are scored, not the model's descriptions.
  • Parallel runs used 2 MPI ranks. At most two requests were in flight at once.
  • Each wrong-setup test used one case. The second test used one model.
  • One AI agent read the models' stated reasons, with no second judge.
  • On another GPU the answer text changed, but the number of positions within 10 % did not.
