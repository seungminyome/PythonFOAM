PythonFOAM: a vision-language observer for OpenFOAM runs

An optional observer for the PODFoam example of PythonFOAM. While OpenFOAM runs, Python draws |U| and p and asks a picture-reading model on the same node what it sees. The answers are recorded, and nothing goes back into the solver. The README says how to run it.

What the model sees: |U| and p at step 250 of a developed backward-facing-step flow, drawn by the running solver and sent to Gemma 4 12B.

What we found

The model was Gemma 4 12B unless a row says otherwise. It got the two pictures above, or a short sequence of them, and a question.

Can it do that while the solver is running?Yes. Asking every 250 steps adds under 1 % to the run time, and every file the solver wrote stayed the same.Works
Between snapshots, is the flow speeding up or slowing down?It reads the trend when the change is clear, about 2 % or more. Smaller changes it misreads.Works for clear changes
Is this run about to crash?It warns only one to five steps before the crash, when the field has already blown up. A simple rule on the numbers does as well.No
Was this run set up wrong?A first test looked promising. A second, stricter test with 29 pairs of runs shows no lead over a simple rule: the model catches more wrong runs but also calls normal runs wrong.Not shown
Does a bigger model help?The small E2B model does not read these pictures reliably. 12B is enough for positions. 31B sees small pressure spots better, but at judging a setup it is no better than a simple rule.Partly

The code part holds too. The PR branches build and pass the bridge validation on OpenFOAM v2012, v2106, v2212 and 8. They also fix a bug in the original PODFoam, where the next snapshot overwrote the first snapshot of each SVD window.

Key numbers

Right means the answered spot lies within 10 % of the plotted range of the true one. The fixed guess is the best single answer given to every picture; where a simple rule on the numbers did better, it is given too. Limitations

  • The tests used 2D laminar flows and one extruded 3D case.
  • Only positions and fixed trend words are scored, not the model's descriptions.
  • Parallel runs used 2 MPI ranks, with at most two requests in flight.
  • The setup tests used one case each, and the second used one model.
  • One AI agent read the models' stated reasons, with no second judge.
  • On another GPU the answer text changes, but not the number of right answers.
